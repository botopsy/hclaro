# M10 implementation and verification

**Status: draft.** Drift scans are implemented for the project opened from the terminal (Go engine adapter, `internal/drift`, operation manager, HTTP API, React **Drift** view, synthetic fixtures). They pass the automated suite and a live loopback run of the real binary against the synthetic CLI (2026-11-06). **No scan has been run with a real Terraform/OpenTofu engine, a real provider or a remote backend.** No real infrastructure, credentials or remote backends were used.

Design and trade-offs: [architecture](architecture.md#drift-scans), [security](../SECURITY.md), [README](../README.md#drift-detection).

## Scope decisions

- **Launch project only.** Plans, applies and imports run only for the project opened from the terminal; drift scans use the same operation manager, slot and root claim. Hub workspace tabs stay read-only and show Drift disabled with the same explanation as Plans. The task's illustrative `POST /api/projects/{id}/drift-scans` became `POST /api/v1/drift-scans`, following the launch plan routes.
- **Refresh-only plan only.** `PlanRequest.RefreshOnly` adds `-refresh-only` to the existing plan argv. There is no `refresh` method, no `apply -refresh-only`, and the artifact is always deleted.
- **Trust the absence of records only when exhaustive.** `no_drift` requires exit 0, a document that is neither errored nor incomplete, no error diagnostics and no unrecognized record.
- **Partial results.** When the engine fails but a saved plan can still be read, its records are shown as an incomplete scan; nothing is concluded about unlisted objects.
- **Freshness.** A scan is bound to workspace, engine, version and the plan context fingerprint (configuration, variable files, data directory, environment, profile). A mismatch withholds the resource list and details rather than showing another context's results.
- **Retention.** In memory only, ten scans, 12 hours. Never persisted.

## M10 acceptance mapping

| Criterion | Evidence |
| --- | --- |
| Explicit **Check Drift** action with a warning about provider APIs, SSO/VPN and backend locks; never on page load; limited to the selected immutable context | Preflight dialog; App and Drift tests show no POST on navigation; one operation slot; the scan records the workspace, variable files and profile context and is bound to the reviewed fingerprint. |
| Capability for `plan -refresh-only` with `-input=false` and a saved output; version-aware parsing; classification of changed, missing, unknown and failures; redaction | `engine.RefreshOnlySupport`; `planArgs`; `plan.Parse` + `drift.Analyze`; failure codes; canary/unflagged-key tests. |
| Labels "recorded in state", "observed during scan", "cannot verify"; refresh-only is not a convergence plan | API fields `recorded`/`observed`/`cannot_verify`; UI column headers and explanatory copy; `[cannot verify]` instead of `[known after apply]`. |
| Summary, resource list, before/after diff, scan time, engine and profile, errors and cancellation; inspector links; separate normal plan | Drift view; `resourceId`; **Run a normal plan…** opens the plan preflight, never starts a plan. |
| No `refresh`, `apply -refresh-only`, `state push` or state writes | No such adapter method; spy tests for both engines; the artifact is deleted on every path and never reaches `Applier`. |
| Remote execution surfaces an unsupported reason; parallel scans limited; sanitized SSE progress | `drift_unsupported` with reason; `ErrBusy`; operation log and `/events`. |
| Store only redacted summaries with short retention; never persist raw plan JSON | In-memory `DriftScan`, ten for 12 hours, no raw document field. |
| Zero drift only after a successful exhaustive scan | `exhaustive` and outcome rules; failure and partial tests in Go and Vitest. |
| Workspace isolation and invalidation | Workspace and fingerprint checks with withheld resources and 409 details. |

## Unresolved

- Real-engine certification: whether Terraform 1.5–1.17 and OpenTofu 1.6–1.13 write a saved plan file when a refresh-only plan fails part-way (Hclaro shows a partial result only if they do), the exact `resource_drift` shapes per provider, and that `resource_changes` is always empty in refresh-only mode (Hclaro refuses the document otherwise).
- A partial result depends on the engine saving an errored plan; without one, a partial provider failure is reported as failed with the diagnostics only.
- "Cannot verify" covers values the engine reports as unknown. An object whose read failed is visible only through the engine diagnostics (with its address), not as a listed record.
- Drift in root outputs is counted, never shown.
- Hub workspace tabs cannot scan; open the project from the terminal.
- Scans do not survive a restart, by design. There is no scheduled scan, notification or reconciliation (out of scope).
- Not run on Windows.
