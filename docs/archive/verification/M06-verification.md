# M06 implementation and verification

**Status: draft.** Guided init is implemented and passes the automated suite and a live loopback run of the real binary against the synthetic CLI (2026-11-05). **No init has been run with a real Terraform/OpenTofu engine, registry or remote backend.** The `init -json` event shapes used for Terraform 1.9+ (`version`, `init_output`, `log`, `diagnostic`) and the human-output error texts are modeled on the documented formats, not certified. No real infrastructure, cloud accounts or remote backends were used.

Design and trade-offs: [architecture](../../architecture.md#initialization), [security](../../../SECURITY.md), [README](../../../README.md#initialize-a-project).

## M06 acceptance mapping

| Criterion | Evidence |
| --- | --- |
| Explicit **Initialize**; never on add, page load, refresh or navigation | Only the wizard's confirm button sends the start POST; `init-status` is a GET that runs nothing; Vitest and spy logs; GET on the start route does not start. |
| Wizard summarizes alias, canonical path, engine + version, backend, workspace context, data dir, lockfile, effects and warnings | `InitWizard` review; `init-review-dark.png`. Version is shown when the session already inspected the project; otherwise "checked before init runs" (GET must not execute the engine). |
| Risks explained; safe default `init -input=false -no-color`; CLI/env flags disclosed; no secrets shown or stored | Effects list and command block; notices name inherited settings without values; no backend credentials are accepted or stored. |
| User-triggered confirm with session token/CSRF; immutable operation record; exclusive per-root lock | Guard allowlist + API tests; `operations.Inits` record; `rootlock.Set` shared with the launch manager; concurrency tests. |
| Streamed, sanitized, bounded events with progress and cancel | Existing SSE route and bounded `Log`; sanitization before `Append`; stage updates; cancel route; leak tests. |
| Refresh on exit; honest status, exit code, next steps, diagnostics; cancel stops the process group | `Finished` drops inspection and contexts; `succeeded` needs exit 0 + data dir, else `unknown`; classified messages; group interrupt/kill. |
| Migration/reconfiguration or interactive input: stop with remediation, never retry with forbidden flags | `backend_migration`, `input_required`, `lockfile_upgrade` codes; argv is fixed; one invocation per request in every test. |
| argv only, `exec.CommandContext`, no API accepting argv or executable paths | `engine.CLI.Init` uses `command()`; the request body has two fields and strict decoding. |
| `-input=false` forced; JSON where supported, conservative human parsing otherwise; success never from text | `InitArgs`; `InitJSON`; success from exit code and data directory only. |
| `TF_CLI_ARGS`/`TF_CLI_ARGS_init` refused and disclosed; credentials preserved but never logged; no secret `-backend-config` | Preflight `unsafe_cli_args`; engine refusal; env pinned and passed through; env-secret scrubbing tests; no backend-config field. |
| Pin engine path, root, data dir, env snapshot and config fingerprint; revalidate before execute | Context ID; pinned `Environ`; `Revalidate` before `init`; edit, symlink-swap and stale-ID tests. |
| Distinguish auth, network, registry, backend config, version mismatch, state lock, migration | Classifier and runner tests for each. |
| No offline promise; no workspace switching assumption | Copy states init may contact registries/backend; init never passes `TF_WORKSPACE` or selects workspaces. |
| Endpoints and statuses | `/api/v1/projects/{id}/init-status`, `/api/v1/projects/{id}/operations/init`, shared `/api/v1/operations/{id}[/events|/cancel]`; statuses `queued`, `running`, `succeeded`, `failed`, `cancelling`, `cancelled`, `unknown`. Request field is `expectedContextId` (camelCase, like every other Hclaro route) rather than the task's `expected_context_id`. |
| Negative cases: migration, interactive question, credentials/network failure, unsupported version, CLI missing, timeout, stale root symlink, cancel, browser closed, `TF_CLI_ARGS_init=-upgrade`, inherited `TF_WORKSPACE`, credentials in output, canary, concurrent commands, two-project isolation, no hidden retry/apply | Covered above. CLI missing is the preflight `missing_cli` reason; timeout shares the cancellation path (the 30-minute limit itself was not waited out in tests). |

## Unresolved

- Real-engine certification of `init` for Terraform and OpenTofu, including Terraform's `init -json` message shapes and OpenTofu's JSON support (OpenTofu is deliberately kept on human output).
- No real registry, provider mirror, module source or remote backend was exercised; the classifier's keywords for those errors are modeled, and unrecognized failures fall back to `init_failed`.
- "Needs reinitialization" is not inferred without running the engine; initialized projects offer **Run init again…**, and the engine's own error (for example `backend_migration`) explains what is needed.
- On Windows, cancellation sends CTRL_BREAK to the engine's process group but the forced kill after the grace period terminates only the engine process. Not run on Windows.
- Removing or repairing a project while its init runs does not stop that init; it stays pinned to the validated root.
- The 30-minute init limit is fixed.
