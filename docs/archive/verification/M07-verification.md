# M07 implementation and verification

**Status: draft.** CLI workspace create, set-CLI-default and empty-workspace delete are implemented and pass the automated suite and a live loopback run of the real binary against the synthetic CLI (2026-11-05). **No workspace command has been run with a real Terraform/OpenTofu engine or a real backend.** The engine error texts used for classification (`already exists`, `doesn't exist`, `is your active workspace`, `currently tracking`, `workspaces not supported`, the `TF_WORKSPACE` override refusal) are modeled on the engines' documented and observed messages, not certified. No real infrastructure, cloud accounts or remote backends were used.

Design and trade-offs: [architecture](../../architecture.md#workspace-lifecycle), [security](../../../SECURITY.md), [README](../../../README.md#manage-cli-workspaces).

## Unresolved

- Real-engine certification of `workspace new/select/delete` for Terraform and OpenTofu, including their exact error texts and the `TF_WORKSPACE` refusal for `new`/`select`.
- No remote backend was exercised. Create and set-default are allowed for `s3`, `gcs`, `azurerm`, `consul`, `cos`, `kubernetes`, `oss` and `pg` on the basis of engine documentation only; `oci` and `swift` are treated as unsupported. Delete is limited to the `local` backend until a remote backend is tested.
- The emptiness check reads `show -json`; it cannot see a write that another process makes between Hclaro's second read and the engine's delete. The engine's own non-force check (under its state lock) is the final guard.
- Hclaro never restores a previous CLI default. Changing the CLI default of the launch project makes its plans and applies refuse until Hclaro restarts (stated in the review).
- On Windows, cancellation sends CTRL_BREAK to the process group but the forced kill terminates only the engine process. Not run on Windows.
- Reviews are kept in memory only (10 minutes, at most 32); a restart discards them.
