# M11 implementation and verification

**Status: draft.** Dependency graphs are implemented for the project opened from the terminal (engine `Grapher`, `internal/graph`, operation manager, HTTP API, React **Graph** view, synthetic fixtures). They pass the automated suite and live loopback runs of the real binary against the synthetic CLI as Terraform and as OpenTofu (2026-11-06). **No graph has been generated with a real Terraform/OpenTofu engine, a real provider or a remote backend.** No real infrastructure, credentials or remote backends were used.

Design and trade-offs: [architecture](../../architecture.md#dependency-graphs), [security](../../../SECURITY.md), [README](../../../README.md#dependency-graph).

## Scope decisions

- **Launch project only**, like plans and drift scans. Hub workspace tabs show Graph disabled with the same explanation. The task's illustrative `POST /api/projects/{id}/graphs` became `POST /api/v1/graphs`, following the launch routes.
- **`graph` with no arguments.** No `-plan`, `-type` or `-draw-cycles`. Terraform 1.7+ then prints a resource-only graph; earlier Terraform and OpenTofu print the full walk graph. Both formats are parsed and give the same resource dependencies for the same configuration (tested).
- **Plan-oriented view = configuration graph + confirmed changes of a reviewed plan.** `graph -plan=<saved plan>` is not used: its apply-walk node names are internal and version-specific, and it would hand the saved apply artifact to another command. Planned changes come only from a stored plan that is complete (not errored, incomplete or deferred) and current (same workspace and engine, unchanged context); otherwise `plan_not_current` with the reason.
- **Dropped nodes.** `(close)`, `root`, `meta.*`, `destroy`/`deposed` and `cleanup` nodes are removed: they depend on everything, so keeping them would make every resource reachable from every other. `(expand)` and `(prepare state)` merge into their node. Other suffixes keep the node as unknown.
- **Derived links.** With internal nodes hidden (default), resources linked only through variables, locals, outputs, module calls or providers are joined by a dashed **derived** link. Reachability is always computed on the full declared graph.
- **Mapping to state** only by address grammar (instance keys removed, quote-aware, same mode). No similarity, type or attribute guessing.
- **Large graphs.** Over 300 nodes: modules start collapsed and the list view is shown first. The list is virtualized.
- **Retention.** In memory, five graphs, 12 hours, as a redacted parsed model; freshness checked on every read like drift scans.

## M11 acceptance mapping

| Criterion | Evidence |
| --- | --- |
| Graph data from version-compatible `graph` DOT output and normalized addresses; internal node names not assumed to map 1:1; unknown/internal nodes kept where needed | `engine.GraphArgs`, `graph.Parse`/`normalize`/`classify`; both formats; unknown and internal kinds; `Annotate` maps by grammar only. |
| Graph Explorer: zoom/pan, fit, module collapse, provider/type filters, select-and-inspect, search, adjacent highlight; accessible list with virtualization | `GraphCanvas`, `NodeList`, filter panel; keyboard pan/zoom/fit; nodes are focusable buttons; Vitest. |
| Configuration and plan-oriented views; inferred links labeled; no cloud topology inference | Configuration graph; plan overlay of a complete, current plan; `derived` links dashed and labeled; no attribute-based inference. `graph -plan` not used (see scope). |
| Upstream, downstream, reverse dependencies, fan-out, neighbours; Potential Impact as reachability; Confirmed Planned Changes only from the full current plan | `graph.Analyze`, `GraphImpact`, `graphPlan` checks, inspector sections and copy. |
| M03 integration: optional Inspect Impact linking to the full plan, no change to apply authorization | **Inspect impact** in the replace summary opens Graph with the plan and address; **View in Plans**; no apply route touched. |
| Cycles, disconnected, dynamic and generated nodes, parse errors, provider/internal nodes, large graphs, ambiguous mapping; cache only context-stamped redacted summaries | Fixtures and tests above; bounded parser; freshness and withholding; in-memory redacted model. |
| No graph action calls `apply`; no claim that an edge guarantees replacement | Spy and fake call assertions; disclaimers in the inspector and README. |
| 1,000-node fixture usable; no secret or raw configuration exposed | Go and Vitest 1,000-node tests; live run; redaction tests; no DOT or labels retained. |

## Unresolved

- Real-engine certification: the exact DOT of Terraform 1.5–1.17 and OpenTofu 1.6–1.13 (fixtures follow the documented shapes), whether `graph` takes a state lock or contacts the backend for every backend type, and how long it runs on very large configurations.
- `graph -plan=<saved plan>` (apply-walk graph) is not offered; plan-oriented dependencies are the configuration graph with confirmed changes overlaid.
- Provider filter uses the type-name prefix, which differs from the configured provider for resources with an explicit `provider` argument from another source; recorded provider addresses are shown in the inspector when the node is mapped.
- `module.x` nodes and module paths in the full graph are configuration paths: per-instance module keys (`count`/`for_each` on modules) appear only in mapped instances.
- Hub workspace tabs cannot generate graphs; open the project from the terminal.
- Graphs do not survive a restart, by design.
- Not run on Windows locally (CI covers Windows unit tests).
