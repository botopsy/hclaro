# M12 implementation and verification

**Status: draft.** Workspace comparison is implemented for Hub workspaces (`internal/compare`, Hub comparison records, HTTP API, React **Compare** page, synthetic fixtures). It passes the automated suite and a live loopback run of the real binary against the synthetic CLI as Terraform and as OpenTofu (2026-11-06). **No comparison has been run with a real Terraform/OpenTofu engine, a real provider or a remote backend.** No real infrastructure, credentials or remote backends were used.

Design and trade-offs: [architecture](../../architecture.md#workspace-comparison), [security](../../../SECURITY.md), [README](../../../README.md#compare-workspaces).

## Scope decisions

- **Built on Hub read contexts.** Each side is opened with `Hub.OpenWith`, exactly like a Hub tab, so the reads are the existing, tested ones (`version`, `workspace list`, `workspace show`, `show -json` with a per-command `TF_WORKSPACE` and the profile environment). The server never reads state files directly. Targets are registered Hub projects only; to compare the project opened from the terminal, save it to the Hub.
- **Deliberate reads.** `POST /api/v1/comparisons` requires `acknowledgeStateRead: true`, sent only from the preflight dialog. Sides already read in this session are reused without running anything (so editing rules does not reread state); **Read both sides again** passes `reload`.
- **Secrets are never compared.** The comparison runs on snapshots the state parser already redacted. A value redacted on either side is `sensitive` and not compared, so an instance with no visible difference but redacted values is **unknown**, not same. Comparing keyed digests of secret values was rejected: it would turn the UI into an equality oracle for secrets.
- **State has no unknown/computed values.** The task's "unknown/computed" treatment maps to redacted values (`unknown`) and to truncated attribute trees; there are no plan-style unknowns in recorded state.
- **Matching** is by exact canonical address. Mapping rules rewrite a left address prefix at a segment boundary; the first matching rule wins; identical addresses claim their right instance before mapped ones, and a collision is uncomparable rather than guessed. A mapping to another type or mode is uncomparable.
- **Providers.** `registry.terraform.io/x/y` and `registry.opentofu.org/x/y` are one provider (with a note), so Terraform and OpenTofu roots of one stack compare. A different namespace (`hashicorp/aws` vs `acme/aws`) is uncomparable. State records no provider versions; the Providers tab says so instead of guessing.
- **Definitions are not persisted.** Targets and rules are kept in the browser tab (`sessionStorage`) and sent with each comparison; results live in server memory (eight, 12 hours). Nothing is written to disk, which also satisfies "never persist ignored secret values".
- **Freshness.** A comparison is bound to its two contexts. Any closure (`reloaded`, `evicted`, `project_removed`, `project_changed`, `initialized`, `workspace_deleted`, `profile_changed`, `profile_removed`), a changed root or a changed profile fingerprint makes it stale and withholds results.
- **Endpoints** follow the repository's conventions (`/api/v1/comparisons`, `…/resources`, `…/export`) rather than the illustrative `POST /api/comparisons` alone.

## Unresolved

- Real-engine certification: comparisons depend only on `show -json`, already exercised for M1 with Terraform 1.5.5; mixed-version provider schemas (an attribute present on one side only because provider versions differ) are reported as differences, which is accurate but can be noisy.
- Comparison definitions (targets and rules) are not saved across sessions; copy them from the exported JSON report if needed.
- Eight read contexts are kept in total; opening many other workspaces can release a side and make a comparison stale (it says so; **Compare again** reads the released side again).
- Values that the redactor hides (including long random-looking strings such as some IDs and digests) are never compared; ignore their paths to reduce **unknown** results.
- The project opened from the terminal must be saved to the Hub to be a comparison target.
- Not run on Windows locally (CI covers Windows unit tests).
