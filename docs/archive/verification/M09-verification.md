# M09 implementation and verification

**Status: draft.** Execution profiles are implemented for launch plans, replacements, imports and applies, Hub read contexts, project tools, init and workspace commands. They pass the automated suite and a live loopback run of the real binary against the synthetic CLI (2026-11-06). **No profile has been used with a real Terraform/OpenTofu engine, a real AWS profile or a remote backend.** Nothing calls a cloud API, and identity verification is not implemented. No real infrastructure, credentials or remote backends were used.

Design and trade-offs: [architecture](../../architecture.md#execution-profiles), [security](../../../SECURITY.md), [README](../../../README.md#execution-profiles).

## M09 acceptance mapping

| Criterion | Evidence |
| --- | --- |
| Versioned per-project registry with the listed fields and a revision; no credentials, keys, tokens, tfvars content or `TF_VAR_*` values | `profiles.json` schema 1; no value fields and strict decoding; validation refuses credential-shaped values and `NAME=value`; canary tests on disk, API, UI. |
| Context selector in the project header and operation dialogs; engine/version, workspace, root, backend/mode, variable files, AWS profile and region; identity labeled unverified; default, clone, edit, remove, per-operation override; tab isolation | Selector in the context bar and on the project page; `ContextSummary` in plan and import dialogs, recorded context in init, workspace, plan review, apply and tools; **Identity not verified** everywhere; manage dialog; per-plan variable file override; `sessionStorage`. |
| Variable files only from approved files, canonical and symlink-safe; filename and metadata, no contents | `ResolveVarFile` at save and before each operation; candidates with size/time; contents never read. |
| Per-child environment, isolated `TF_WORKSPACE`, rejected `TF_CLI_ARGS*`, local SSO/credential providers without copying secrets | `Compose`; `WithEnvironment`/`SelectedWorkspace`; case-insensitive refusal; only alias names passed. |
| Summary before plan, replace, import, init and workspace commands; revision bound; no mid-flight redirection; no implicit identity lookup | Fingerprint required at start; stored context and environment per operation and artifact; deletion-during-run test; no cloud API. |
| Operation metadata holds only sanitized profile name, revision and non-secret context | `ExecutionContext` on operations, plans, approvals; canary checks. |
| Survives restart; every supported operation visibly uses the context; backward compatible without a profile | Reopen tests and live restart; recorded context in every view; unchanged requests (all pre-existing tests pass with unchanged request bodies). |

## Unresolved

- Real-engine and real-AWS certification: that Terraform/OpenTofu and the AWS provider honor `AWS_PROFILE`/`AWS_REGION` from the child environment as expected with SSO profiles, and that `-parallelism`/`-lock-timeout` behave identically across Terraform 1.5–1.17 and OpenTofu 1.6–1.13.
- Optional identity verification (for example `sts get-caller-identity` on explicit opt-in) is not implemented; identity is always "not verified".
- Only AWS aliases exist. Other providers' profile/region variables (Azure, Google Cloud) are not modeled; their inherited environment is passed unchanged.
- `-parallelism` and `-lock-timeout` apply to plans only; applying a saved plan still takes no options (`Applier` has none), so an apply uses the engine defaults.
- For the project opened from the terminal, a profile cannot change the engine or workspace: Hclaro must be restarted with `--engine`, or the workspace changed outside Hclaro and read again. Hub workspaces remain read-only.
- A profile-bound launch plan passes the snapshot's workspace explicitly as `TF_WORKSPACE`; if the CLI default changes in a terminal afterwards, the profile-bound plan still targets the reviewed workspace (the profileless path keeps refusing with `workspace_changed`).
- PATCH replaces the whole profile; there is no partial update.
- Profiles of a project removed while the profile file is unreadable remain in the file, unreachable.
- Not run on Windows; the symlink tests skip there.
