# M13 implementation and verification

**Status: draft.** Plan and execution history is implemented: `internal/history` (storage, retention, migrations, plan summary comparison, exports, Git identity), an `operations.Recorder` hook in both operation runners, HTTP routes under `/api/v1/history`, a `--export-history` command-line flag and a React **History** page. It passes the automated suite and a live loopback run of the real binary against the synthetic CLI (2026-11-06). **No operation was recorded from a real Terraform/OpenTofu engine, a real provider or a remote backend.** No real infrastructure, credentials or remote backends were used; the live run's `apply` went to the synthetic engine and its fixture state.

Design and trade-offs: [architecture](architecture.md#operation-history), [security](../SECURITY.md), [README](../README.md#operation-history).

## Scope decisions

- **Integrated with the existing lifecycle, not a second tracker.** The launch `Manager` (plans, replace/import plans, applies, drift scans, graphs) and the Hub `Inits` runner (initializations, workspace commands, tools) call one `Recorder` when an operation starts and when it ends. History never starts, tracks or re-runs a process. The in-memory **Operations** lists and live logs are unchanged.
- **Only what the runners already expose.** Records are built from the sanitized `Operation`, the redacted `plan.Review`, the drift summary and sanitized log events. A second `clean` pass withholds anything credential-shaped before writing and again after reading.
- **Plan summaries are addresses and actions only.** Counts, up to 300 `{address, action}` pairs, output/drift counts, variable file names and a 12-character context fingerprint. Attribute and output values are not kept, so the comparison of two summaries is about *what* each plan touched and how, not attribute diffs.
- **Planned vs executed.** A plan's own outcome is `planned` / `not_planned`. When an apply ends, the plan it used gets an `execution` link. Applies are `applied` (worded *Engine reported applied*, `verified: false`), `partial` (started and did not finish cleanly) or `not_applied`. An entry left `running` by a stopped process becomes `unknown` / `interrupted` at the next start.
- **Projects are identified without paths.** Hub projects by ID and alias; a launch project outside the Hub by an ID derived from its root and its folder name. The root path is never stored or exported.
- **Git identity** is read from `.git/HEAD`, the ref file or `packed-refs` (worktrees via `gitdir`/`commondir`), never by running `git`. Dirty trees are not detected; this is stated in the UI copy and README.
- **Exports.** The browser downloads a report (`GET /history/export`, like the M12 comparison export) and never sends a path. "Explicit export path validation" is implemented for the command line: `--export-history FILE` accepts only a new `.json`/`.md` file in an existing folder, outside `.terraform` and `.git`, refuses links and existing files and writes with `O_EXCL` and `0600`. Log lines are never exported; `omitted` lists what was left out and how many values were withheld.
- **Endpoint names** follow the repository (`/api/v1/history`, `…/{id}`, `…/compare`, `…/export`, `…/retention`); `DELETE /api/v1/history` with `{confirm: true}` clears all or one project's entries.
- **Schema 1 is the first history format.** The migration chain exists and is exercised with a synthetic schema 0 in tests; `DefaultMigrations` is empty.
- **Demos stay isolated.** `make demo` and `make dev` now set `HCLARO_CONFIG_DIR` to `.cache/demo/config`, so demo plans and applies are not recorded in the real per-user history.
- **Two processes** sharing a configuration folder merge entries: every change re-reads the file when its size or modification time changed, and the last writer wins per entry. An operation running in another process can briefly look *interrupted* to a process that starts meanwhile; its final record replaces that.

## Unresolved

- Real-engine certification: recording depends only on the existing runners' metadata, which is engine-independent; no new engine command was added.
- A secret that is neither a known input nor credential-shaped (for example a short human-chosen password a provider echoes into a diagnostic) is not recognized, exactly as in the live log; the history keeps at most the last 40 such sanitized lines per operation.
- Dirty Git working trees are not detected; the commit shown is what was checked out, not necessarily what was planned.
- Plan comparison is by address and action only; attribute-level differences between two historical plans are not available because values are not stored.
- Concurrent Hclaro processes merge entries but are not locked against each other; simultaneous writes can lose the slower writer's latest change to a single entry until that operation records again.
- Not run on Windows locally (CI covers Windows unit tests; `GOOS=windows go vet` passes).
