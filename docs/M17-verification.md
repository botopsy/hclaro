# M17 implementation and verification

**Status: draft.** Cost impact estimation is implemented as a new package `internal/cost` (provider abstraction with an allowlisted Infracost CLI runner, plan minimization, exact-decimal report aggregation, session service with opt-in, cancellation and staleness, and a local aggregate store), cost routes for the launch project's plans, a `--strict-local` flag, and a connected **Cost estimate** tab in the plan review.

Design and trade-offs: [architecture](architecture.md#cost-estimates), [security](../SECURITY.md), [README](../README.md#cost-estimates-infracost-optional).

## Scope decisions

- **Launch project only.** Plans, preflight and apply exist only for the project opened from the terminal, so estimates do too. The task's `POST /api/projects/{id}/cost-estimates` is illustrative; the route is `POST /api/v1/plans/{id}/cost-estimates` with a server-issued plan ID and an empty body.
- **Infracost CLI v0.10, optional.** Hclaro never installs it or reads its API key. v0.9 and v0.11+ are refused (`cli_unsupported`). Infracost always prices through a pricing API, so there is no offline mode; `--strict-local` turns the feature off with *Not available in strict local-only mode*.
- **Opt-in per session, estimate per click.** The opt-in names the disclosure version the user saw and is held in memory; restarting Hclaro turns the feature off again. Each estimate is a separate CSRF-protected POST.
- **Minimized input, not the saved plan.** The cost input is derived from the `show -json` document while it is in memory, kept with the plan in memory only, and written to a private temporary file only while the CLI runs. The binary saved plan (which holds plaintext secrets) is never given to the cost tool, and estimates work for every reviewed plan, not only the applicable one.
- **Coverage definition.** Coverage counts changed managed resource instances (not no-ops, data reads or deposed objects): (estimated + partially estimated) ÷ (changed − resources the provider reports as having no price). Usage-based-only, unsupported, forgotten and unknown-action changes count against coverage and carry no amount.
- **Persistence.** Only aggregate totals are saved (`cost-estimates.json`, last 50). History (`history.json`) is unchanged because its strict schema 1 would need a migration that older builds refuse.

## Known limitations

- **Never run against real Infracost.** Command flags, environment variables and the JSON schema follow Infracost v0.10 documentation and were exercised only with the synthetic CLI and report. Before release, certify with a real Infracost v0.10 against a disposable plan, including whether the minimized input prices the same as the full plan JSON (for example resources whose price depends on dropped expressions or tags).
- Hclaro controls the input and environment, not what the Infracost CLI sends: the pricing attributes kept in the input (instance types, sizes, regions, resource IDs) leave the device, and Infracost may add its own run metadata.
- No usage file: usage-based charges are not priced and are reported as caveats. No billing data, committed spend, discounts or background repricing (out of scope).
- Only one provider (Infracost). A self-hosted pricing API is used if configured, but it is still treated as remote; strict mode stays off for it.
- The opt-in does not survive a restart, by design.
- Deposed objects are not line items (their delete is not priced).

## Manual verification

1. `make demo` (synthetic `terraform`, `aws` and `infracost` first on `PATH`) and open the printed URL.
2. **Plans → Run plan**, then the **Cost estimate** tab: confirm *Cost estimation is off* and no Estimate button.
3. **Review data disclosure…**: check the endpoint, *What can leave this device*, *Never sent* and the authentication text; the turn-on button is disabled until the box is ticked. Turn it on.
4. **Estimate cost**: check `+9.89 USD / month (partial)`, *Covers 3 of 6 cost-bearing changes (50%)*, the caveats, the type table and that IAM role, subnet, security group, S3 bucket, `aws_lb.edge` and `random_password.unused` show labels, not amounts.
5. Edit or add a `.tf` file in `fixtures/project` (revert afterwards): the estimate becomes *Out of date* and the plan cannot be estimated again. **Review and apply…** still works for a current plan whatever the estimate state.
6. Restart with `INFRACOST_PRICING_API_ENDPOINT=http://offline.invalid make demo` (or `auth.invalid`, `old.invalid`, `slow.invalid` to try **Cancel**) for the failure states, and run `bin/hclaro --strict-local …` for strict local-only mode.
