# M08 implementation and verification

**Status: draft.** Validate, format check, providers and output metadata are implemented. They pass the automated suite and a live loopback run of the real binary against the synthetic CLI (2026-11-05). **No project tool has been run with a real Terraform/OpenTofu engine.** The `validate -json` document, the `providers` tree and the error texts used for classification (`Missing required provider`, `Module not installed`, `Backend initialization required`, `flag provided but not defined`, …) are modeled on the engines' documented and observed formats, not certified. No real infrastructure, cloud accounts or remote backends were used.

Design and trade-offs: [architecture](architecture.md#project-tools), [security](../SECURITY.md), [README](../README.md#project-tools).

## M08 acceptance mapping

| Criterion | Evidence |
| --- | --- |
| Validate: `-json` when supported, fallback to human diagnostics; error/warning, location, status, elapsed time; not drift detection; no automatic init, Init offered | JSON parser with preceding-text tolerance and human fallback; findings with `file:line:column` (text only); exit code and duration in result and log; copy in cards and results; `not_checked` + **Review Init on the project page**. |
| Format check: read-only `fmt -check -no-color`, optional `-recursive`; list of files; no plain `fmt`, no HCL writes | Fixed argv; tree fingerprint unchanged; files listed only from the enumerated set. Optional sanitized `-diff` is **not implemented** (see Unresolved). |
| Providers: requirements and warnings; not proof of identity; no downloads/upgrades | Parsed tree (configuration/state, module, constraint); warnings as findings; identity caveat in card and result; argv fixed to `providers`. |
| Outputs: names, types, `sensitive`, errors; raw output never forwarded/cached/logged; no value reveal | Decoder without a value field; stdout never leaves the adapter; stderr only classified; hidden-name count; canary and unflagged-secret tests at engine, runner, Hub, HTTP, UI and live levels. |
| Operation center: status per project and workspace, refresh, bounded sanitized log, cancel, links; history local and ephemeral | **Operations in this project** with workspace filter, refresh, `OperationLog` (SSE replay, cancel), project-page link; in-memory `Inits` history (50 finished, 10 logs, running never evicted). |
| Whitelisted server-built argv; no generic CLI, `-chdir`, paths, shell or executable override | Route per tool, body `{contextId, recursive?}` with unknown fields refused; `exec.CommandContext` via `commandEnv`. |
| Immutable context at submission; per-child `TF_WORKSPACE` for workspace-dependent reads; bound across UI switches | Hub read context (project, root, engine executable, workspace) + pinned environment; executable path and identity checked; mid-run switch test. |
| Check-only labeling; honest about `providers` without init and `validate` needing providers | Card copy; partial providers result; `plugins_missing`/`init_required` → not validated. |
| Enumerate files for recursive check; no traversal of linked folders outside the root | `FormatScope` with folder and file counts shown; linked folders refused/skipped; linked files outside the root refused. |
| Robust against non-JSON, invalid format, unsupported versions, exit codes, missing engines | Fallback, `output_unreadable`, `output_too_large`, `engine_version`, `missing_cli`, `unsupported_flag`; exit code always reported. |
| Reject inherited `TF_CLI_ARGS`, command-specific variants, conflicting `TF_WORKSPACE`, untrusted paths; secrets out of logs | Refused before any process and again in the adapter; `TF_WORKSPACE` dropped/replaced with notice; file names only when local; scrubbed environment secrets. |
| Parallel projects and workspace switch keep targeting; cancellation and partial output classified | Hub and HTTP tests; `cancelled` discards partial output; failed `providers` marks `partial`. |
| API/auth/CSRF/Host/Origin per operation | HTTP test table for each route; live curl checks. |

## Unresolved

- Real-engine certification of `validate -json`, `fmt -check`, `providers` and `output -json` for Terraform 1.5–1.17 and OpenTofu 1.6–1.13, including exit codes (`fmt -check` exit 3 is assumed only as "non-zero") and the error texts used for classification. The `providers` tree format in particular is parsed from documented examples only.
- Sanitized `-diff` for format check (optional in the task) is not implemented: a diff quotes configuration source, which can contain hard-coded secrets.
- Whether OpenTofu's `fmt` reads `.tofu`/`.tofutest.hcl` in every supported version is assumed from its documentation; the enumerated set only affects which reported paths are shown.
- Tools run in an open Hub read context, and opening one reads the workspace's state (`show -json`) as in M05. The Tools view works even when that read fails (for example, an uninitialized project).
- Format check and validate failures are reported with operation status `failed` (with result "Needs formatting"/"Not valid"), not a separate status; the result column distinguishes them from errors.
- History is shared with init and workspace commands (50 finished operations, 10 logs) and is lost on restart; there is no opt-in persistent history.
- On Windows, cancellation sends CTRL_BREAK to the process group but the forced kill terminates only the engine process. Symlink tests skip where links are unavailable. Not run on Windows.
