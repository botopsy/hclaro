# M05 implementation and verification

**Status: draft.** The Workspace Hub is implemented and passes the automated suite and a live loopback run of the real binary against the synthetic CLI (2026-11-05). **No Hub workspace has been read with a real Terraform/OpenTofu engine or a remote backend**, so `TF_WORKSPACE` handling is verified only against the synthetic CLI, which follows the documented behavior. No real infrastructure, cloud accounts or remote backends were used.

Design and trade-offs: [architecture](architecture.md#workspace-hub), [security](../SECURITY.md).

## M05 acceptance mapping

| Criterion | Evidence |
| --- | --- |
| Hub reachable from every screen; launch from a root unchanged; Hub outside a root; `--hub`; `--path` compatible | Sidebar **Projects**; CLI flow above; `TestHubArguments`; live run; explicit bad `--path` still fails. |
| Explicit registry: add by folder chooser or path, alias, reorder, pin, last used, remove without deleting; per-user config, versioned JSON, atomic writes | Registry tests, API tests, Vitest. |
| Canonical paths, duplicate rejection, actionable errors, no recursive scan, untrusted strings as data, disconnected projects kept with repair/remove | `Canonical`/`sameDir` tests; browse lists one level; aliases validated and rendered as text; `missing`/`path_changed` statuses with **Repair path**. |
| Project cards: alias, path, engine/version, init status, workspace count, backend, last opened, errors; no account guessing | `ProjectCard`; version and count shown once inspected, otherwise "not checked"/"not listed yet". |
| Workspace navigator via official CLI, loading/empty/error; UI selection is per tab, no global select; simultaneous dev/prod tabs | `workspace list` inspection; context isolation tests and live two-tab run; spy logs. |
| Immutable `(project, root, engine, workspace, data dir, profile)` snapshots; per-child `TF_WORKSPACE`; inherited conflicts documented; no leakage on switch | Context key and scoped store; `workspace_mismatch` guard; README and architecture; keyed `Workbench` and context-scoped query keys; Vitest switch test. |
| Search, recents, keyboard, focus, onboarding/error states, production-like warning without inference | Hub search (Cmd/Ctrl+K), recents, arrow-key lists, modal focus via `useModal`, empty/onboarding and error states, `productionLike` hint with explicit tooltip. |
| Loopback, session, Origin/Host, CSRF on all new endpoints; no init/select/refresh/mutation on navigation | Guard tests; GET routes never run commands; inspection and contexts are CSRF POSTs running only read commands. |
| `TF_DATA_DIR` respected and shown; not rewritten | Shown read-only; absolute value refused for Hub reads; never written. |
| Stable root and engine identity; stale and deleted contexts rejected | Executable resolved once per context; `Verify` re-checks the directory identity; `context_closed` reasons. |
| Test plan: two engines and same alias, symlink duplicate, missing directory, default/dev/prod isolation without `workspace select`, unregister during read, corrupt/unreadable registry, cross-site POST, missing token, malicious paths, missing executable, unsupported version, canary | All covered above. Missing executable and unsupported version: inspection and context both report `missing_cli` / `engine_version` with no state (`TestMissingOrUnsupportedEngineIsReportedHonestly`). "Remote backend unavailable" is covered only by the generic `workspace_list`/`state_unavailable` diagnostics; no remote backend was simulated. |

## Unresolved

- Real-engine certification of `TF_WORKSPACE` for `workspace show` and `show -json` with local, S3 and `cloud` backends. HCP Terraform/`cloud` mapping of `TF_WORKSPACE` to remote workspace names differs from local backends and has not been exercised.
- The registry has no cross-process lock: two Hclaro processes changing it at the same instant keep the last write.
- Engine version and workspace lists are cached only for the session; cards show "not checked" until a project is opened.
- Plans, applies and imports for Hub workspaces are deliberately out of scope (later milestones would need per-context operation managers and fingerprints).
- `make cross` and CI were not run for this change.
