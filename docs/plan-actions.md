# Plan actions Hclaro supports

Hclaro classifies each resource change and output change in a saved plan by the ordered
`change.actions` list from `show -json`. It recognizes exactly these lists:

| `actions` (engine order) | Shown as | Notes |
|---|---|---|
| `["create"]` | Create | |
| `["update"]` | Update | In-place change |
| `["delete"]` | Delete | Includes deposed objects |
| `["delete","create"]` | Replace | Destroy, then create |
| `["create","delete"]` | Replace | Create the replacement first (`create_before_destroy`) |
| `["read"]` | Read | Data source read during apply |
| `["no-op"]` | No change | Also used by imports without attribute changes |
| `["forget"]` | Forget | Removed from state, object kept |

The list is defined in `internal/plan/plan.go` (`SupportedActions`, `Classify`).

## Unsupported action combinations fail closed

Anything else is **unsupported**. That includes `["update","delete"]`, repeated actions such as
`["delete","delete"]`, combinations such as `["read","delete"]`, an empty or missing list on an
output, and action names Hclaro does not know.

- The plan can still be reviewed. Unsupported changes are labeled **Unsupported**, counted in
  `unsupportedActions`, and described in a warning. Values are redacted as usual.
- **Apply is unavailable.** The server refuses the plan with the stable code `unknown_actions`.
  It does not keep the saved plan file, and the preflight's `plan.eligible` check blocks. Approval
  and apply return `409 unknown_actions`. Typing the destructive confirmation phrase does not
  override this. The server checks again immediately before it would start the engine.
- A resource change with no actions or more than four actions is malformed, so the whole plan is
  rejected.
- Drift records (`resource_drift`) are informational and never applied, so they do not affect
  eligibility.

Inspect the plan with the engine's own CLI (`terraform show <planfile>` / `tofu show <planfile>`)
and apply it there if you have checked it is correct.

## Stopping a plan or apply

Cancel in the UI, a timeout or Ctrl+C in the terminal sends the engine one interrupt; the engine
runs in its own process group, so the terminal's Ctrl+C never reaches it directly. A plan that
has not stopped 15 seconds later is killed. An apply gets 10 minutes: providers finish in-flight
calls and the engine writes state, and killing it earlier can lose state or leave a lock. An
interrupted apply is reported as uncertain unless the engine exits successfully, in which case it
is reported as applied. When Hclaro is stopped during an apply it says so and waits for the
engine; pressing Ctrl+C again exits at once and leaves the engine to stop on its own.

## Reporting a new combination

If a supported engine version emits a combination that should be supported, open an issue with:

1. The engine and version (`terraform version` / `tofu version`).
2. The action list and the resource type only, for example:

   ```json
   {"address": "example_thing.demo", "type": "example_thing", "change": {"actions": ["update", "delete"]}}
   ```

3. What the engine's documentation says the combination means.

Do **not** attach real plans, state, `before`/`after` values, account IDs or resource names from
your infrastructure. A synthetic example like the one above is enough. Sanitized fixtures live in
`fixtures/plan/` and are generated by `scripts/fixtures/generate-plans.py`. `unknown-actions.json`
is the reference example for an unsupported combination.
